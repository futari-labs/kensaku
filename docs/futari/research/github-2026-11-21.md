## What GitHub can enforce today

Nothing at branch level, on either `main` or `dev` (G4). GitHub cannot prevent a push to `main`, a direct merge into `main`, deletion or force-push of `main`, or a merge into `dev` without passing checks. Pull request checks still run and report (`CI`, `Futari contract`), but they do not block merging.

## Enforcement gaps (explicit)

1. **No server-side protection on `main` or `dev`.** Protection is process-only (D-023, D-025): the plan, playbook, and worker briefs forbid agents from pushing to, merging into, or enabling auto-merge into `main`.
2. **Agents act with the owner's admin credentials.** The `gh` token on this machine is the owner's (G3). Anything an agent does through it is indistinguishable on GitHub from the owner acting. Even if rulesets were available, an admin token can edit or delete a ruleset, so an agent using these credentials could remove the protection it is subject to. The token's `workflow` scope also lets an agent change `.github/workflows/*`; `futari-contract.yml` runs from the PR head with the base branch's checker scripts, so it is an integrity check for cooperative agents, not a security boundary.
3. **Auto-merge is enabled** at repository level (G5). Without protection rules, auto-merge has no required checks to wait for. The plan therefore forbids `gh pr merge --auto` on every PR.

## Ways to close the gaps (owner decisions, not part of this plan's authority)

- **Server-side rules on `main`:** either make the repository public (rulesets become available on Free) or upgrade the organization to a paid plan (GitHub Team for organizations). Then add a ruleset on `main`: restrict updates, block force pushes and deletion, require a pull request with the owner's approval, and an **empty bypass list** (rulesets apply to admins unless they are listed as bypass actors).
- **Credential separation:** run agents under a separate identity without admin rights (a machine user or GitHub App with Write permission). With a ruleset on `main`, that identity cannot push to, merge into, or change rules on `main`, while the owner's admin account remains able to promote. Without this, gap 2 remains even with a ruleset.
- **Local guard:** a Claude Code project permission deny list or a PreToolUse hook in `.claude/settings.json` that blocks `git push` to `main`, `gh pr merge` for PRs whose base is `main`, `gh pr merge --auto`, and `gh api` writes to branch, ruleset, or repository-setting endpoints. This is a client-side control: it constrains Claude Code sessions in this repository only, not other tools or a human.
- **Disable repository auto-merge** (`allow_auto_merge: false`) in the repository settings.
