## Consequences for the plan

1. Under D-005 ($0 additional spend, free credits only), Affiliate.com structured offers are unavailable (F7, F8). Merchant offers must come from ordinary index results (F1) whose price and availability exist only in page text, highlights, summaries, or a synthesized `outputSchema` output (F3-F6).
2. Kensaku must therefore extract and validate price, currency, availability, and merchant itself or from Exa synthesis, and must cite the merchant URL plus a retrieval timestamp (D-006). Exa synthesis can hallucinate or return null (F6), so deterministic validation must reject offers that lack a source URL, a parseable price, or a currency.
3. The free budget of about $10 per month bounds live testing. Example: one Auto search with summaries for 10 results costs about $0.007 + $0.01 = $0.017 (F9), so roughly 580 such requests per month.
4. Whether the free plan refuses requests once credits run out (no overage) is an assumption to confirm with the owner. F8 suggests it does, because no payment method is required.

Observed limitations:

- **L1 Wrong product.** For the nonexistent "Zorblax QX-9000 toaster" (S5), Exa returned a Sur La Table page marked as a listing with a $449.95 price for "Premium Stainless Steel Toasters". Without an identity check, Kensaku would show a real price for the wrong product.
- **L2 Mixed regions.** With `userLocation: "US"`, results still included GBP (logitech.com UK pages), EUR (amazon.nl), and AUD (officeworks.com.au) listings.
- **L3 Merchant and URL disagree.** Review articles (theverge.com, howtogeek.com) were extracted as "merchant: Best Buy, $169.99, in_stock". The summary's merchant name does not prove that the URL sells the item.
- **L4 Major retailers without prices.** Best Buy and Target pages returned `price` absent in every case (6 results), most likely because they render prices client-side. Amazon, Sony, Adorama, Logitech, Williams Sonoma, and Macy's returned prices.
- **L5 No observation time.** `snapshotAt` was never present. The only honest timestamp is the time Kensaku received the response; the page crawl time is unknown.
- **L6 Synthesis mis-attribution.** The search `outputSchema` call (S7) returned 5 structured offers with per-field grounding, but attributed Target and Best Buy offers to a `deal.ai` aggregator URL. The schema of an array of objects was accepted despite the documented depth-2 limit.
- **L7 Price plausibility is unverifiable.** Sony WH-1000XM5 prices ranged $169.99-$278 across sources on the same day. Kensaku cannot tell a sale from an extraction error; it can only show the source and the label "last observed".
- **L8 Fresh crawl.** `maxAgeHours: 0` (S6) cost the same as a cached request and did not change any extracted price.
- `/answer` (A1) returned a 619-character comparison with bracketed citation markers and 8 citations, which fits the comparison step.

Consequences for the design:

1. Use one search result per offer (per-result `summary`), not synthesized offer lists (L6). The offer URL is then the result URL by construction.
2. Deterministic acceptance rules: `isProductListing = true`; price > 0; ISO currency in the run's region currency set; URL from this run's results; the product identity tokens (model number or distinctive name tokens from the candidate) appear in the extracted product name or page title (L1); show the merchant as the URL's host, with the extracted name secondary (L3).
3. `retrievedAt` is Kensaku's response receipt time, labeled as retrieval time, not observation time (L5).
4. Expect about 2-4 valid offers per product from 5 results. Using 10 results costs about $0.017 per product search.
5. Do not use `maxAgeHours: 0` (L8).
